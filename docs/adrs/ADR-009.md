# ADR-009: AI tooling strategy — Copilot, CodeRabbit, local LLM stretch goal

> **Status:** Accepted
> **Date:** 2026-05-23
> **Deciders:** Repository owner

---

## Context

The project requires AI tooling across four functions: in-editor code generation and chat, autonomous issue implementation via coding agent, automated PR review, and CI/CD automation. All four functions must be covered before Phase 1 begins, because the AI-native workflow is the primary engineering method — not a supplement to a conventional workflow.

The selection constraints are: zero additional recurring cost (existing GitHub Copilot Individual subscription is the cost ceiling), all AI actions must be traceable in Git history or PR comments, and every change must pass a human review gate before merge. The hardware profile (Intel Pentium N3710, 8 GB RAM) constrains local LLM inference — any tool requiring on-cluster inference must be evaluated against the available compute.

A CI/CD runner strategy decision is embedded in this ADR. The self-hosted runner executes on the k3s cluster, which does not exist until Phase 1 completes. This creates a bootstrap dependency: PR validation during Phase 1 cannot use the self-hosted runner. The runner strategy must account for this.

Coding agent integrates directly with GitHub Issues and branches. ## Decision

The platform uses GitHub Copilot Individual for in-editor completions, Copilot Chat for planning and architectural discussion, the Copilot coding agent for autonomous issue implementation, and Copilot PR review for first-pass inline review comments. CodeRabbit free tier provides deep PR analysis alongside Copilot review. GitHub Actions handles all CI/CD orchestration, using GitHub-hosted runners for PR validation and a self-hosted runner on the k3s cluster for post-merge deployment and smoke tests. Gitleaks runs in every PR workflow for secret scanning. Ollama with a locally-hosted LLM is adopted as a Phase 4+ stretch goal, conditional on a hardware upgrade or a dedicated inference node being available.

---

## Rationale

GitHub Copilot Individual was selected because it covers all four required AI functions within the existing subscription — in-editor assistance, coding agent, and PR review are all included. No additional tooling cost is incurred. Every Copilot action is surfaced in PR comments and Git history, satisfying the traceability requirement.

The dual-runner strategy addresses the bootstrap dependency directly. GitHub-hosted runners execute PR validation (linting, `kubeval`, Helm lint, Gitleaks, Copilot review, CodeRabbit) before the cluster exists, because they require no local infrastructure. The self-hosted runner on k3s executes only post-merge jobs (ArgoCD sync, smoke tests, Grafana annotations) that logically require the cluster to be running. This means Phase 1 PR CI operates entirely on GitHub-hosted runners. The self-hosted runner is added to the cluster in Phase 2 without requiring any change to the PR workflow definition.

CodeRabbit free tier was added because it provides a materially different review signal to Copilot — change impact analysis, dependency mapping, and summary views — at no cost for public repositories. The two review tools are complementary rather than redundant.

The Ollama option was rejected for Phase 1–3 because the hardware profile cannot run a useful LLM model (7B parameters minimum) alongside Kubernetes system pods and application workloads within the 8 GB RAM constraint. The decision is deferred, not discarded: if a hardware upgrade occurs or a dedicated inference node is added, Ollama is the preferred local inference tool. See Phase 4 scope in `docs/architecture.md` Section 8.

Commercial review tools were rejected because they add cost above the zero-additional-cost ceiling and provide no capability not already covered by Copilot review and CodeRabbit.

---

## Consequences

### What this makes easier

- The entire AI-native workflow — planning, implementation, review, and CI/CD — operates within the existing Copilot Individual subscription at zero additional cost
- Every AI action is traceable: coding agent commits appear in branch history, PR review comments are permanently recorded, CI results are posted to the PR
- Agent instruction files (`.github/agents/`) are plain Markdown and tool-agnostic — switching to a different coding agent (Claude Code, Cursor) requires no changes to the instruction files
- The dual-runner strategy means Phase 1 bootstrap CI works immediately without a running cluster

### What this makes harder

- The self-hosted runner creates a sequencing dependency: post-merge deployment jobs cannot run until the k3s cluster and the runner are provisioned in Phase 2. Phase 1 merges do not trigger ArgoCD sync automatically.
- Coding agent output quality is directly proportional to issue quality. Vague or incomplete issues produce vague or incomplete implementations. The issue template and upload script exist to enforce the quality contract, but the discipline must be maintained throughout the project.
- Local LLM inference (Ollama) is deferred to Phase 4+. Commit message generation, issue summarisation, and changelog automation that would benefit from local inference are not available until the hardware constraint is resolved.
